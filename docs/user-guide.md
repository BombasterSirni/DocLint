# DocLint — инструкция пользователя

## Быстрый старт

1. Откройте страницу DocLint в браузере. Регистрация не нужна.
2. Выберите профиль требований: «ГОСТ 7.32-2017», «Типовая методичка
   (кегль 14)» или свой профиль кафедры.
3. Перетащите `.docx` в зону загрузки или нажмите «Выбрать файл».
   Для знакомства нажмите «Проверить пример» — отчёт появится без файла.
4. Исправьте нарушения в Word и проверьте документ ещё раз, пока отчёт
   не станет пустым.

Файл обрабатывается в браузере: он не отправляется на сервер, не сохраняется
в `localStorage` и исчезает из памяти при закрытии вкладки. После первого
открытия страница работает без интернета.

## Как читать отчёт

Сверху показана сводка: сколько нарушений и в скольких категориях. Кнопки
категорий фильтруют карточки. Кнопка «Печать / PDF» открывает системную
печать — можно сохранить отчёт в PDF.

В карточке:

* **Абзац 37** или **Абзацы 12–51** — место в документе (нумерация абзацев
  идёт по порядку в `document.xml`, включая пропущенные элементы);
* **Шрифт / Интервал / …** — категория нарушения;
* **Найдено** — фактическое оформление;
* **Требуется** — значение из профиля;
* **Как исправить** — путь в меню Word.

Одинаковые нарушения в соседних абзацах объединяются в одну карточку.
Нарушения полей страницы показываются отдельными карточками
«Параметры страницы».

## Профиль требований

### Встроенные пресеты

* **ГОСТ 7.32-2017** — поля 30/15/20/20 мм, Times New Roman, кегль не меньше
  12 пт, интервал 1,5, отступ 12,5 мм, по ширине.
* **Типовая методичка (кегль 14)** — то же, но кегль не меньше 14 пт.

Встроенные профили нельзя изменить или перезаписать.

### Свой профиль кафедры

1. Нажмите «Свой профиль».
2. Проверьте название и числа из методички: поля, шрифт, минимальный кегль,
   интервал, отступ первой строки, выравнивание.
3. Нажмите «Сохранить профиль». Он появится в списке «Мои профили» и
   сохранится в этом браузере.

Профиль можно выгрузить кнопкой «Экспорт .json» и отправить одногруппникам.
Они загружают файл кнопкой «Импорт .json» и проверяют работы по тем же
правилам. При импорте профиля с `id` встроенного пресета создаётся копия
с новым `id`.

## Что проверяется

| Параметр | Допуск |
| --- | --- |
| Левое, правое, верхнее, нижнее поля | ±0,5 мм |
| Шрифт | точное совпадение, без учёта регистра |
| Размер шрифта | не меньше указанного, ±0,5 пт |
| Междустрочный интервал | ±0,05 |
| Абзацный отступ первой строки | ±0,5 мм |
| Выравнивание | точное совпадение |

Проверяются только обычные абзацы основного текста. Оформление вычисляется с
учётом стилей Word: стиль по умолчанию, цепочка `basedOn`, символьные стили,
прямое форматирование абзаца и фрагмента, шрифты темы.

## Что не проверяется

* титульный лист (всё до первого явного разрыва страницы, разрыва раздела
  или «с новой страницы»);
* заголовки, оглавление, таблицы, пустые абзацы;
* подписи рисунков и таблиц, список литературы, нумерация страниц,
  колонтитулы;
* содержание и грамотность текста.

Если в документе нет ни одного разрыва, границу титульного листа определить
нельзя — проверяется весь документ.

## Если значение не удалось определить

DocLint не угадывает. Если интервал задан в точках (`exact`/`atLeast`) или
отступ — в символах (`firstLineChars`), правило пропускается. В строке
«Проверок недоступно: N» видно, сколько проверок не выполнено. Это лучше
ложного нарушения, но такие места стоит проверить в Word вручную.

## Частые вопросы

**Почему отчёт пустой, а нормоконтроль нашёл ошибки?**
MVP проверяет только шесть параметров основного текста. Титульный лист,
заголовки, таблицы, список литературы и подписи не входят в проверку.

**Почему один и тот же документ даёт разные результаты по разным профилям?**
Профили отличаются требованиями: например, кегль 12 допустим по ГОСТ, но не
по методичке с кеглем 14.

**Почему нарушение в абзаце, который выглядит правильно?**
Проверяется итоговое оформление с учётом стилей и темы. Нажмите в Word
«Главная → Абзац» и «Главная → Шрифт» для этого абзаца. Если значение
неизвестно, правило пропускается, а не показывается как ошибка.

**Документ в формате `.doc`.**
Откройте его в Word и сохраните как `.docx`.

**Файл больше 20 МБ.**
Уменьшите размер (например, сожмите изображения) и загрузите снова. В MVP
один файл за раз.

**Есть отслеживаемые изменения.**
Примите исправления перед проверкой: изменения не анализируются отдельно.

**Документ не изменяется?**
Нет. DocLint только читает файл и показывает отчёт.

## Для преподавателя

1. Откройте ссылку на DocLint.
2. Нажмите «Проверить пример» — появится отчёт по демонстрационному документу
   с намеренными ошибками.
3. Загрузите любой `.docx` студента. Сервер, установка и учётные записи не
   нужны.

## Приватность

* файл не покидает браузер;
* нет регистрации, аналитики, внешних API и рекламы;
* в `localStorage` хранятся только профили, созданные пользователем;
* service worker кэширует только статические файлы приложения, не документы.
