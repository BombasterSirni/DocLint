# DocLint

Проверка оформления учебных работ (курсовых, отчётов, ВКР) в формате `.docx`
по ГОСТ 7.32-2017 или требованиям методички кафедры — прямо в браузере.

Перетащите файл на страницу и получите список нарушений: номер абзаца, первые
слова, найденное и требуемое значение, подсказку, где исправить в Word.
Файл не загружается на сервер, регистрация не нужна, аналитики нет.

## Что проверяется (MVP)

| Параметр | Как проверяется |
| --- | --- |
| Поля страницы | левое, правое, верхнее, нижнее; допуск ±0,5 мм |
| Шрифт | точное совпадение с профилем (без учёта регистра) |
| Размер шрифта | «не меньше» указанного кегля; допуск ±0,5 пт |
| Междустрочный интервал | кратность (1,0 / 1,5 / …); допуск ±0,05 |
| Абзацный отступ | первая строка; допуск ±0,5 мм |
| Выравнивание | по ширине / левому / центру / правому краю |

Оформление вычисляется с наследованием Word:
`docDefaults → цепочка basedOn стиля абзаца → символьный стиль (w:rStyle) →
прямое форматирование абзаца → прямое форматирование фрагмента (run)`.
Учитываются шрифты темы (`theme1.xml`), twips, половины пункта и кратность
интервала.

**Пропускаются:** титульный лист (всё до первого явного разрыва страницы, разрыва раздела
или «с новой страницы»), заголовки (`heading`/`outlineLvl`), оглавление (`TOC`), таблицы, пустые абзацы,
абзацы с неизвестным стилем. Документ не изменяется.

**Не проверяются:** титульный лист, заголовки, оглавление, таблицы, подписи
рисунков и таблиц, список литературы, нумерация страниц, колонтитулы,
содержание текста.

## Запуск

Сайт статический: сервер нужен только чтобы отдать файлы (ES-модули не
работают по `file://`). После первого открытия service worker кэширует
приложение, и проверка работает без сети — в том числе после перезагрузки
вкладки.

```bash
python3 -m http.server 8080
# открыть http://localhost:8080
```

Проверка преподавателя: открыть ссылку → «Проверить пример» → отчёт; затем
загрузить любой свой `.docx`.

Пошаговая инструкция пользователя: [`docs/user-guide.md`](docs/user-guide.md).

## Профили требований

Встроены два пресета:

* **ГОСТ 7.32-2017** — поля 30/15/20/20 мм, Times New Roman, ≥12 пт,
  интервал 1,5, отступ 12,5 мм, по ширине;
* **Типовая методичка (кегль 14)** — те же параметры с кеглем ≥14 пт.

Свой профиль создаётся формой на странице, хранится в `localStorage`
(ключ `doclint.profiles`, версия схемы 1), выгружается в `.json` и
импортируется у одногруппников. Встроенные профили перезаписать нельзя:
импорт с их `id` создаёт копию с новым `id`.

## Тесты

```bash
npm test          # node --test tests/*.test.mjs, Node.js ≥ 20
bun test          # альтернатива без Node.js
```

Покрыты: перевод единиц Word, разбор XML (DOMParser и запасной парсер),
наследование стилей и тема, исключения MVP, правила с допусками, группировка
отчёта, профили, локальное хранилище, импорт/экспорт JSON и сквозные проверки
реальных `.docx` (включая демонстрационный файл).

Демонстрационный файл можно пересобрать:

```bash
bun tools/make-sample.mjs   # sample/demo.docx
```

## Публикация на GitHub Pages

Workflow `.github/workflows/ci.yml` запускает тесты на каждый push/PR.
Собранный статический сайт публикуется в отдельный репозиторий
`doclint-site`, откуда GitHub Pages отдаёт готовые файлы:

```bash
tools/publish-site.sh
```

Скрипт собирает `dist/`, копирует `index.html`, `assets/` и `sw.js` и делает
push в `main` репозитория `doclint-site`. Источник: репозиторий `DocLint`,
сайт: https://bombasterirni.github.io/doclint-site/. Все пути относительные,
поэтому сайт работает и в подкаталоге GitHub Pages.

## Контракты модулей

```js
checkDocument(file, profile) → Promise<Report>
validateProfile(json) → Profile
saveProfile(profile), exportProfile(id), importProfile(file)

Report {
  totalChecked, skippedCount, uncheckedCount, countsByRule, summary,
  violations: [{ paragraphIndex, preview, ruleId, actual, expected, hint }]
}
```

Ошибки имеют единый формат `{ code, message, details }`; коды:
`INVALID_FILE`, `FILE_TOO_LARGE`, `INVALID_DOCX`, `INVALID_PROFILE`,
`CHECK_FAILED`. В интерфейсе показывается понятное сообщение и действие.

## Ограничения и решения

* Один файл `.docx` за раз, до 20 МБ; `.doc` не поддерживается — сохраните в
  `.docx`.
* Поля страницы берутся из финального `sectPr` документа; разные поля в
  разных разделах в MVP не проверяются.
* Интервал, заданный в точках (`exact`/`atLeast`), и отступ в символах
  (`firstLineChars`) не угадываются: правило честно пропускается и попадает в
  счётчик непроверенного.
* Титульный лист определяется по первому явному разрыву страницы, разрыву
  раздела или свойству «с новой страницы». Если разрывов нет вообще, границу найти нельзя — проверяется весь
  документ (иначе короткие работы без разрыва давали бы пустой отчёт).
* Отслеживаемые изменения не анализируются отдельно: перед проверкой лучше
  принять исправления.
* Отчёт хранится только в памяти вкладки до следующей проверки или закрытия.
* В `localStorage` лежат только пользовательские профили, не текст работы.
* Service worker кэширует только статические файлы приложения; документы
  пользователя в кэш не попадают.

## Приватность

Вся обработка выполняется в браузере: `JSZip` распаковывает `.docx`,
`DOMParser` читает XML, правила сравнивают значения. Сетевых запросов,
кроме загрузки статических файлов самой страницы, нет. Изображения из
документа не извлекаются — читаются только `document.xml`, `styles.xml` и
`theme1.xml`.
